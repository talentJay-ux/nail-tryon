# 生成式"客图上手"PoC · 记录（2026-11-09）

## 1. 为什么换路线

线上 demo（YOLOv8 指甲分割 + Canvas 平面盖色）的客户反馈是"效果太丑"，具体三点：角度不对放错位置、没有融合、颜色不真实。
看过 `docs/validation/*-comparison.jpg` 后判断这是路线上限，不是参数问题：平涂的色块没有甲面曲率、没有跟原图光源走的高光、指缘无过渡、肤色对颜色零影响。继续在上面调是"没找到根因就换变体"。

业界做"参考照 → 顾客手"这件事的头部产品都已是生成式：玩美移动 Perfect Corp 的 AI Nail Transfer 接口（文档原话 "a powerful generative AI solution"）、美图设计室"AI 美甲上手"、Agalaz；YouCam Nails 这类 AR 实时叠加只能用自带图库，不能传客图。

决定：静态图先做，实时 / AR 推迟；美学是底线，目标是"惊艳客户"而不是把贴图摆上去。

## 2. 需求（当前版本，仍在讨论）

- 输入 A：客图，多为小红书式手照（10 根甲一个主题 + 2～3 根点缀甲），也可能是色卡板或拼图。
- 输入 B：顾客手照。建议店里引导拍摄（手背朝上、五指张开、光线均匀、素甲）作为硬要求，待拍板。
- 输出：款式真实渲染到顾客手上的候选图，2～4 张供挑选。
- 真实度定义：重新渲染指甲区域（曲面、反光、指缘、通透感），手 / 皮肤 / 背景保持不变。
- 甲型长度：默认保留顾客自己的，`--adopt-shape` 按客图延长；默认值待拍板。
- 验收建议：10 组输入，美甲师盲打 1～5 分，均分 ≥ 4 且无穿帮（手指数、点缀甲位置、肤色漂移）。同输入在 Perfect Corp playground 跑一遍当业界标尺。

## 3. 方案（四段）与进度

1. **提取**：从客图得到逐指 JSON（底色、质感、点缀、金属颜色、甲型、长度）。这份 JSON 同时是美甲师的参数面板。— 未做（第 2 片）
2. **生成**：JSON + 手照 + 客图 → N 张候选，并行。— 已做（`tryon.py`，目前只喂两张图 + 固定提示词 v1）
3. **自动检查**：手指数、指甲以外像素变化（分割蒙版比对）、视觉模型按 JSON 逐项打分排序。— 未做
4. **交付**：对比报告（`report.html`）、批量网格（`batch.py`）、微信分享图（`export_wechat.py`）。— 已做

模型：`gemini-3-pro-image`（Nano Banana Pro，正式 id；`-preview` 在 v1 下 404）。免费档对它配额为 0，必须付费档。

## 4. 实测

| 项目 | 数字 |
| --- | --- |
| 1K 单张 | 20 s（1 张） |
| 2K 单张 | 平均 34.5 s，28～49 s（50 张） |
| 单张费用 | ≈ $0.134，1K / 2K 同价，4K $0.24（第三方转述官方价目） |
| 并发 | 3 个进程并行调用未被限流 |
| 可靠性 | 56 次请求得到 53 张图；3 次模型以 IMAGE_RECITATION 拒绝出图（全部在同一张流传很广的小红书客图上），无其他失败 |
| 一位顾客 3 张并行 | 约 40～50 s，约 ¥3 |

**第一组真实结果**（顾客短甲手照 × 长款灰蓝猫眼 + 银色雕花宝石客图，A 保留甲型 3 张 / B 延长 3 张）：

- 好：六张手、袖口、房间全部原样，无手指变形；猫眼流光、立体雕花、椭圆宝石有体积且光照与房间一致；B 组延长到方圆长款无贴图感；B-2 几乎是客图的一比一布局。
- 差（全是忠实度）：银色雕花六张里五张画成金色；点缀甲数量 1～3 根不等（客图 2 根）；部分蓝色偏饱和，客图是灰调。
- 结论：模型"画得真"没问题，"画得和客图一样"要靠第 1 段提取把款式写明确。指甲以外未见漂移，合成守门暂不需要。

## 5. 与旧方案对比

| 维度 | 分割 + 平面盖色 | 生成式 |
| --- | --- | --- |
| 真实感 | 差，路线上限 | 好 |
| 漏检 / 变形 | 侧向手指漏检，花纹甲 9 漏 3 | 首批 6 张无漏无变形；46 张批量待逐张评审 |
| 复杂款式 | 做不到 | 雕花、宝石、猫眼、延长都能画 |
| 款式忠实度 | 高（精确色值） | 中（颜色与点缀位置会漂） |
| 速度 / 费用 / 隐私 | 实时、零费用、不出浏览器 | 35 s、≈ ¥1 / 张、照片上云 |
| 确定性 | 有 | 无，多张挑 |

旧仓库的分割模型继续用于裁客图、合成守门、自动检查；色号与单指编辑界面可演化为参数面板。

## 6. 本地 5080（16 GB）判断

能跑：FLUX.2 klein 4B / 9B、Qwen-Image-Edit-2511 4bit、FLUX.1 Kontext / Fill fp8。跑不动：Qwen-Image-Edit 原精度（约 40 GB）、FLUX.2 dev 32B、OmniTry（28 GB）。
LMArena 图像编辑榜上闭源 Gemini 比最强开源编辑模型高约 130～150 分；预测不微调时本地在立体雕花、延长重画手指、双图理解三处明显落后，纯色 / 渐变 / 法式差距小，蒙版重绘保证指甲外不动则比云端强。
这是预测不是实测；机器可达后用同一组输入各跑 3 张对照。自托管超过云端的前提是用门店真实三元组（素手、客图、成品）微调；不要用 Gemini 输出训练（接口条款）。
